# Calibration against expert judgement

Most supplier risk scorecards use weights that were set once in a workshop and never validated.
The **Calibration Agent** closes that loop: it learns weights from how category managers actually
judge their suppliers, so the model gets closer to practice with every review cycle.

## Inputs

- Factor ratings of the suppliers in scope (computed by the Scoring Agent).
- A holistic **expert label** per supplier: `expert_risk_score`, a **0–100 score** on the same
  scale as the model score (*"How risky is this supplier overall?"*), collected e.g. during the
  annual supplier review. Not every supplier needs one.

### Why 0–100 labels and not classes?

Labels are expected as **0–100 values**. The expert's **class is derived from the label** with the
model's own thresholds (e.g. 62 → *high*), so labels and model results are directly comparable.
A numeric label carries more information than a class (55 and 69 are both *high*, but not the
same). It also makes the fit a simple least-squares problem. The report shows both views:

- **MSE**: score-level fit (score points²)
- **class agreement**: share of suppliers whose model class equals the class derived from the label

Ordinal labels (classes only) are a possible extension, see below.

Only suppliers with a label **and** complete factor data are used, because missing-data re-weighting
would make the score non-linear in the weights. Excluded suppliers are listed in the report.

> **Sample labels are synthetic.** `data/calibration_portfolio.json` is generated by
> `examples/generate_calibration_dataset.py` from a hidden weighting plus noise. It demonstrates
> that the method works (calibration moves the weights towards the hidden weighting). It says
> nothing about how well the default template fits any real supplier base.

## Optimisation problem

For n suppliers with rating vectors x_i (1..5) and labels y_i (0..100), find effective factor
weights θ:

```
s_i(θ) = (x_i·θ − 1) / 4 · 100

minimise    1/n Σ ((s_i(θ) − y_i) / 100)²   +   λ · ‖θ − θ_anchor‖²
subject to  θ_f ≥ w_min  for all f
            Σ θ_f = 1
```

| Term | Meaning | Config |
|---|---|---|
| first term | mean squared error between model and expert | — |
| λ‖θ − θ_anchor‖² | ridge pull towards the **configured default weights**; stabilises results with few labels | `regularization` (0.05) |
| θ_f ≥ w_min | every criterion keeps a minimum influence | `min_factor_weight` (0.02) |
| Σθ = 1 | weights stay a proper weighting | — |

This is a convex quadratic program. It is solved with SciPy `SLSQP` and an analytic gradient
(`tools/calibration.py`). The design goal is that calibration **adjusts** an expert-defined
methodology rather than replacing it with a black box.

**Anchor vs. prior.** The regularisation always pulls towards the *configured defaults*, never
towards the result of a previous calibration. The "MSE before" is measured with the weights that
are currently active (defaults or previously approved weights). As a result, repeated calibration
on the same labels converges to the same weights. Otherwise each run would drift a little further
away from the methodology. A test covers this.

## Acceptance, approval and feedback loop

1. MSE and class agreement are computed before (active weights) and after (calibrated weights)
   on the same sample.
2. The new weights are **accepted** only if the solver converged and the MSE drops by at least
   `min_improvement` (default 5 %).
3. Accepted weights are then either
   - **auto-applied** (`auto_apply: true`): they become active immediately, are written to the
     weight store, and the supervisor routes back to the **Scoring Agent** for one re-score, or
   - **proposed** (`auto_apply: false`): the run **pauses at human review** (LangGraph
     `interrupt()`). A reviewer approves or rejects. On approval the weights are stored with the
     reviewer's name and the portfolio is re-scored.
4. Old vs. new weights (factor and dimension level), MSE, class agreement, sample size, exclusions
   and the stored file are written to `state["calibration_report"]` and the audit trail.

For weights that drive real supplier decisions, `auto_apply: false` is the recommended setting.

## Persisting weights: the weight store

```
data/weights/
├── global_v001.yaml
├── global_v002.yaml
└── plastics_v001.yaml
```

- Each applied weight set becomes a **new version** of its scope. Files are never overwritten.
- Each file records the timestamp, status (`approved` / `auto_applied`), approver, model name and
  version, and the calibration metrics.
- Every run with a weight store **starts from the latest version per scope**. Older versions
  can be loaded for comparison or rollback: `WeightStore(dir).load("global", version=1)`.
- Files whose factors no longer match the risk model are skipped with a warning.

## Scope: global vs. material group

- **MVP:** one weight set per run. Without `material_group` the scope is `global`.
- Run with `material_group="plastics"` and the agent calibrates only on that group and stores
  the result under that scope. The Scoring Agent always uses the most specific weight set
  available, so global and group-specific weights can coexist.

## Usage

```bash
# auto-apply (template default) and persist
supplier-risk --data data/calibration_portfolio.json --calibrate --weights-dir data/weights

# per material group
supplier-risk --data data/calibration_portfolio.json --material-group plastics --calibrate --weights-dir data/weights

# with approval: set `auto_apply: false` in your model YAML, then decide in the terminal
supplier-risk --data data/calibration_portfolio.json --model my_model.yaml --calibrate \
              --weights-dir data/weights --review interactive
```

```python
from supplier_risk_agent import SupplierRiskEvaluator
from supplier_risk_agent.models import ReviewDecision

ev = SupplierRiskEvaluator.from_json("data/calibration_portfolio.json", "my_model.yaml", weights_dir="data/weights")
state = ev.run(calibrate=True)

request = ev.pending_review(state)            # None if nothing to decide
if request and request["proposed_weights"]:
    state = ev.resume(state["run_id"], ReviewDecision(reviewer="jane.doe", approve_weights=True))
print(state["calibration_report"].stored_as)
```

## Practical guidance

- **Sample size.** With 10 factors, aim for clearly more than 10 labelled suppliers per scope.
  `min_labels` (default 8) is a hard floor; regularisation does the rest.
- **Label quality.** Collect labels *before* experts see the model score, to avoid anchoring.
- **Treat weights like a model release.** Review the proposal, approve it, and commit the new
  weight file.
- **Overfitting check.** Planned: k-fold cross-validated MSE in the report.

## Possible refinements

- cross-validation and confidence intervals for weights
- ordinal labels (low/medium/high/critical) with ordinal regression
- calibrating class thresholds in addition to weights
- hierarchical (partial pooling) calibration across material groups
